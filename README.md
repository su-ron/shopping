### 1. 引言

#### 1.1 目的

本文档为**蓝牙耳机专卖网购网站**提供完整、清晰的需求定义，作为使用Claude Code实现功能的主要依据。文档涵盖前台用户购物流程（商品展示 → 购物车 → 下单 → 扫码支付）和后台管理功能，确保系统形成闭环。

#### 1.2 项目范围

**包含功能**：

- 商品展示（列表、详情、搜索、筛选，针对蓝牙耳机特性优化）
- 购物车功能（添加、修改、删除、选中计算）
- 用户登录/注册/个人信息管理
- 订单管理（创建、查看、状态流转）
- 支付功能：**支付宝扫码支付** + **微信扫码支付**
- 基础后台管理（商品CRUD、订单管理）

**不包含（后续迭代）**：

- 真实物流对接、优惠券、积分、秒杀
- 推荐算法、评价系统（可模拟简单展示）
- 多语言支持

#### 1.3 定义与缩写

- **TWS**：真无线蓝牙耳机
- **ANC**：主动降噪
- **扫码支付**：PC端通过支付宝/微信App扫描二维码完成支付
- **沙箱环境**：开发测试使用的支付宝沙箱和微信支付测试环境

### 3. 具体功能需求

#### 3.1 用户模块

- **注册**：用户名/手机号/邮箱 + 密码 + 验证码（模拟）
- **登录**：账号密码登录 + JWT Token（支持7天有效）
- **用户中心**：个人信息、收货地址管理（增删改查、默认地址）、我的订单
- 登录后游客购物车自动合并

#### 3.2 商品模块（蓝牙耳机专属优化）

**3.2.1 商品分类**

- 一级分类：真无线耳机、骨传导耳机、颈挂式耳机、其他蓝牙耳机
- 二级分类：主动降噪、运动防水、游戏低延迟、办公通勤等

**3.2.2 商品数据模型**（推荐字段）

- products（SPU）：
  - id, name, brand, price, original_price, stock, sales
  - category_id, description, images (JSON数组，至少5张)
  - specs (JSON)：蓝牙版本、降噪类型、电池续航、防水等级、驱动单元、音频编解码、重量、适用场景等
- skus（SKU）：
  - id, product_id, spec_name（颜色/配置）, spec_value（黑色/白色等）, price, stock

**3.2.3 商品列表页**

- 分页 + 筛选（价格区间、降噪类型、防水等级、续航、适用场景）
- 搜索（商品名、品牌、关键词如“降噪”“骨传导”）
- 排序（综合、销量、价格）

**3.2.4 商品详情页**

- 图片轮播 + 多角度图（相关图片可以在淘宝或者京东上去获取）
- SKU选择器（颜色按钮 + 配置切换，实时更新价格/库存/图片）
- 规格参数表（清晰展示蓝牙耳机核心参数）
- 卖点标签（ANC主动降噪、40小时续航、IPX5防水等）
- 加入购物车 / 立即购买
- 相关推荐（同价位、同场景耳机）

#### 3.3 购物车模块

- 添加商品（支持SKU + 数量）
- 购物车列表：缩略图、名称、规格、单价、数量、小计
- 修改数量、删除、选中/全选
- 实时计算总价
- 游客本地存储（localStorage），登录后合并

#### 3.4 订单模块

**3.4.1 订单流程**

1. 购物车结算 → 订单确认页（显示地址、商品清单、总金额）
2. 提交订单 → 生成待支付订单
3. 进入支付页 → 选择支付方式
4. 完成支付 → 订单状态更新

**3.4.2 订单状态**

- 待支付 → 已支付（待发货） → 已发货 → 已完成 → 已取消

**3.4.3 订单管理**

- C端：我的订单列表（状态筛选）、订单详情
- B端：订单列表、查看详情、修改状态（发货、取消）

#### 3.5 支付模块（核心新增内容）

**3.5.1 支持的支付方式**

- **支付宝扫码支付**（电脑网站支付模式）
- **微信扫码支付**（Native支付）

**3.5.2 支付页面功能**

- 显示订单信息（商品、金额、地址）
- 支付方式选择（支付宝图标、微信图标）
- 点击后生成并展示大尺寸二维码
- 显示支付金额、订单号、剩余支付时间（建议15-30分钟倒计时）
- 支持刷新二维码
- 支付成功后自动跳转订单详情页或成功提示页

**3.5.3 支付业务流程**

1. 用户在订单确认页提交订单，生成“待支付”订单。
2. 跳转至支付页，选择“支付宝”或“微信”。
3. 后端调用支付平台接口生成二维码（支付宝返回二维码链接，微信返回code_url）。
4. 前端展示二维码图片。
5. 用户使用支付宝/微信App扫描二维码完成支付。
6. 支付平台异步回调后端接口。
7. 后端验证后更新订单状态为“已支付”，扣减库存。
8. 前端可通过轮询查询订单状态，确保支付成功后跳转。

**3.5.4 支付相关数据模型**

SQL

```
-- 支付记录表（payments）
- id
- order_id
- payment_no          -- 商户支付单号
- payment_type        -- alipay / wechat
- amount
- status              -- 0待支付 1已支付 2失败 3退款
- trade_no            -- 支付宝/微信交易号
- qr_code_url         -- 二维码图片地址或链接
- notify_time
- create_time

-- orders表补充字段
- payment_type        -- alipay / wechat
- payment_time
```

**3.5.5 技术与测试要求**

- 开发阶段使用**支付宝沙箱**和**微信支付沙箱**（或模拟支付）。
- 支持异步回调 + 主动查询支付状态（前端轮询）。
- 支付超时自动取消订单（建议30分钟）。
- 所有支付接口必须使用HTTPS并进行签名验证。

#### 3.6 后台管理模块

- 商品管理：CRUD、批量上下架、规格参数维护
- 订单管理：列表、详情、状态修改、发货操作
- 可选：支付记录查看

### 5. 主要页面与接口清单

**主要前台页面**：

- / 首页（场景推荐 + 爆款耳机）
- /products 商品列表 + 筛选
- /product/:id 商品详情
- /cart 购物车
- /checkout 订单确认页
- /pay/:orderNo 支付二维码页（支付宝/微信）
- /orders 我的订单

**核心API**（示例）：

- 商品相关：GET /api/products、GET /api/products/:id
- 购物车：POST /api/cart/add、GET /api/cart
- 订单：POST /api/orders/create
- 支付：POST /api/orders/:orderNo/pay （参数：payment_type=alipay/wechat）→ 返回二维码信息
- 查询：GET /api/orders/:orderNo/status
- 回调：POST /api/pay/notify/alipay、POST /api/pay/notify/wechat

### 🚀 快速开始

#### 1. 环境要求
- Node.js 16+
- MySQL 8.0+
- npm 或 yarn

#### 2. 安装依赖
```bash
npm install
```

#### 3. 数据库设置
1. 创建数据库：
```sql
CREATE DATABASE bluetooth_earbuds_store CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 导入数据库架构：
```bash
mysql -u root -p bluetooth_earbuds_store < database/schema.sql
```

3. 配置数据库连接：
编辑 `database/config.js` 文件，设置正确的数据库连接信息。

#### 4. 启动服务器

##### 方式一：同时启动前端和后端（推荐）
```bash
npm run dev:all
```

这将同时启动：
- 前端静态服务器：http://localhost:8000
- 后端API服务器：http://localhost:3000

##### 方式二：单独启动后端API
```bash
npm run api:dev
```

后端API服务器将在 http://localhost:3000 启动。

##### 方式三：单独启动前端
```bash
npm run dev
```

前端静态服务器将在 http://localhost:8000 启动。

#### 5. 访问网站
- 前端页面：http://localhost:8000
- 后端API：http://localhost:3000
- API文档：查看 [README-API.md](README-API.md)

#### 6. 测试认证系统
```bash
node test-auth.js
```
