### 2.3 核心函数

```
┌─────────────────────────────────────────────────────────────────┐
│                        ImportCer                                │
├─────────────────────────────────────────────────────────────────┤
│ updateField(key, value)      → 更新字段 + 清除对应错误         │
│ handleSelectP12Path()        → CEF Query 选择 p12 路径          │

│ handleBlur(field)            → 失焦触发校验                     │

│ handleNext()                 → 校验 → CEF Query → 提交          │

│ toggleAdvance()              → 展开/收起 Advanced Setting       │
```

#### 2.3.1 handleNext 流程

```
handleNext()
  ├── validateForm()
  │   ├── validateField('p12Name')
  │   ├── validateField('p12Path')
  │   ├── validateField('password')
  │   ├── validateField('confirmPassword')
  │   ├── validateField('keyAlias')
  │   ├── validateField('validity')
  │   ├── validateField('CSRName')
  │   └── validateField('csrPath')
  │   └── 任一失败 → return
  │
  └── setLoading(true)
      └── 构造 ImportCertificatePayload
          ├── firstName = form.firstName || form.keyAlias
          └── 不含 confirmPassword
      └── new CefQueryCfg('ImportCertificate')
          ├── .data = JSON.stringify(payload)
          ├── .success → setLoading(false)
          │   ├── response.success → onNext()
          │   └── !response.success → message.error(...)
          └── .failure → setLoading(false), message.error(...)
      └── sendCefQuery(cfg)
```

### 2.4 表单校验实现

采用**字段级独立校验 + 全量校验**的双层模式：

- **失焦校验**（handleBlur）：用户离开字段时立即执行单字段校验，即时反馈
- **提交校验**（validateForm）：点击 Next 时执行全部必填字段校验

校验函数 `validateField(field)` 返回 `boolean` 并更新对应的 `errors[field]` 状态。

**注意**：Advanced Setting 非必填字段（firstName, orgUnit, organization, city, province, countryCode）在 `validateField` 中直接 `break` 不校验，但 `firstName` 的默认值处理在提交时由业务逻辑保证：

```typescript
firstName: form.firstName || form.keyAlias
```

### 3.1 接口定义

```java
}
```

#### CefQueryCallback（接口）

```java
public interface CefQueryCallback {
    void success(@NotNull String response);

}
```

### 3.2 事件注册

```java
// CefEventConstants.registerAll()
handlerMap.put(EVENT_IMPORT_CERTIFICATE, new ImportCertificateHandler());
handlerMap.put(EVENT_SELECT_FILE_PATH, new SelectFilePathHandler(project));
// ↑ 需要 project 参数以打开原生文件选择器
```

### 3.3 SelectFilePathHandler

**用途**：响应前端 📁 图标点击，打开 IntelliJ 原生目录选择器。

```
onQuery(data, callback)
  └── EXECUTOR.execute()
      ├── 解析 JSON → 获取 title
      ├── FileChooserDescriptorFactory.createSingleFolderDescriptor()
      ├── ApplicationManager.getApplication().invokeAndWait()
      │   └── FileChooser.chooseFile(descriptor, project, null)
      ├── 构造响应 { path: "..."" }
      └── callback.success(json)
```

**关键设计决策**：

1. **EDT 线程**：`FileChooser.chooseFile()` 必须在 EDT 调用，通过 `invokeAndWait()` 从异步线程同步到 EDT
2. **AtomicReference**：在 EDT 闭包与外层线程间传递 `VirtualFile` 引用
3. **使用目录选择器**：`createSingleFolderDescriptor()`，选择的是文件夹路径而非文件本身
4. **异常处理**：任何异常都返回 `{"path": ""}` ，前端不更新

### 3.4 ImportCertificateHandler

**用途**：处理前端 Next 提交的证书导入请求。

```
onQuery(data, callback)
  └── EXECUTOR.execute()
      ├── 1. Gson.fromJson(data, Request.class)
      ├── 2. validateRequest(request)
      │   ├── p12Name → 非空 + 格式（字母/数字/-/_/.p12）
      │   ├── p12Path → 非空
      │   ├── password → 非空 + 最小长度 6
      │   ├── keyAlias → 非空 + 无空格
      │   ├── validity → 正整数
      │   ├── firstName → 非空
      │   ├── orgUnit → 非空
      │   ├── organization → 非空
      │   ├── city → 非空
      │   ├── province → 非空
      │   ├── countryCode → 非空 + /^[A-Z]{2}$/
      │   ├── CSRName → 非空
      │   └── csrPath → 非空
      │   └── 失败 → CefResponse.fail("CERT_INVALID_INPUT", msg)
      │
      ├── 3. doImport(request)  // TODO: 实际实现
      │   → 生成 KeyPair + 自签名证书 + PKCS12 文件 + CSR
      │   → 返回 Result(certificateId, validFrom, validTo)
      │
      ├── 4. CefResponse.ok(result) → callback.success(json)
      └── 异常 → CefResponse.fail("CERT_INTERNAL_ERROR", msg)
```

### 3.5 DTO 设计

前后端数据结构严格镜像：


| TypeScript                 | Java                                   | 说明         |
| -------------------------- | -------------------------------------- | ------------ |
| `ImportCertificatePayload` | `ImportCertificateData.Request`        | 请求体       |
| `ImportCertificateResult`  | `ImportCertificateData.Result`         | 响应体       |

## 5. 安全设计

### 5.1 密码处理

- 前端密码字段仅存在于 React 组件状态（内存），不涉及 localStorage/sessionStorage
- 前端 `confirmPassword` 字段不包含在发送给后端的 payload 中
- 后端密码仅在 `doImport()` 期间用于操作 KeyStore，完成后不持久化
- 所有日志路径不应记录 password 字段

### 5.2 输入校验

- 前端：格式校验（正则）+ 必填校验（用户友好提示）
- 后端：严格校验（商业逻辑安全），即使绕过前端也安全
- 路径校验：前端基本格式，后端最终的 exists/writable 检查

## 6. 错误处理

### 6.1 前端错误处理


| 场景             | 处理                                        |
| ---------------- | ------------------------------------------- |
| 表单字段不合法   | 字段级错误展示`.field-error`                |
| 后端返回业务错误 | `message.error()` antd 全局提示             |
| CEF 通信错误     | `failure` 回调 → `message.error()`         |
| JSON 解析异常    | catch →`message.error('Invalid response')` |

### 6.2 后端错误处理


| 场景           | 处理                                                      |
| -------------- | --------------------------------------------------------- |
| 请求参数不合法 | `CefResponse.fail("CERT_INVALID_INPUT", msg)`             |
| 密码错误       | `CefResponse.fail("CERT_INVALID_PASSWORD", ...)`          |
| 路径不可写     | `CefResponse.fail("CERT_PATH_NOT_WRITABLE", ...)`         |
| 文件已存在     | `CefResponse.fail("CERT_FILE_EXISTS", ...)`               |
| 生成失败       | `CefResponse.fail("CERT_GENERATION_FAILED", ...)`         |
| 未预期异常     | `CefResponse.fail("CERT_INTERNAL_ERROR", e.getMessage())` |

所有错误均通过 `callback.success()` 返回（而非 `callback.failure()`），由前端通过 `response.success` 字段区分成功/失败。`callback.failure()` 仅用于 CEF 通信层面的异常（极少发生）。

## 7. 国际化

所有文本通过 `getMessage(key)` 函数获取，集中定义在 `resource/properties/internationalization.ts` 中。

文本分类：

- `title` — 页面标题
- `label.*` — 表单标签文本
- `placeholder.*` — 占位符文本
- `error.*` — 校验错误消息
- `help.*` — 帮助提示（title + content）
- `button.*` — 按钮文字
